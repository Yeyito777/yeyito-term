# Experiment: build with `-O2` instead of `-O3`

Date: 2026-05-21
Branch: `gpu-renderer-prototype`

## Hypothesis

Several parser/write-path experiments suggest that code size and instruction-cache
pressure may matter as much as individual arithmetic operations.  Building with
`-O2` instead of `-O3` could reduce code bloat and improve cursor/repaint wall
or CPU time while preserving LTO and `-march=native`.

## Patch tested

In `config.mk`:

```diff
-CFLAGS = -O3 -march=native -flto
+CFLAGS = -O2 -march=native -flto
```

No source changes were made.

## Validation

With the patch applied:

```sh
make clean
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.

After rejection and revert:

```sh
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.

## A/B benchmark vs current build flags

Benchmark output was saved to `/tmp/st-ab-o2-two.jsonl`.

Median kept-iteration results:

| Workload | Wall speedup | CPU ratio | Result |
|---|---:|---:|---|
| cursor_updates | `0.9828x` | `1.0111x` | cursor regression |
| repaint | `0.9768x` | `1.5568x` | severe repaint regression |
| scroll_ascii | `0.9984x` | `0.7905x` | CPU win, wall tie/slight loss |

## Decision

Rejected and reverted.

The `-O2` build reduced ASCII-scroll CPU in this run, but it regressed both
primary blockers: cursor wall/CPU and repaint wall/CPU.  Keep `-O3 -march=native
-flto` for now.

Do not retry plain `-O2` in the same form.
