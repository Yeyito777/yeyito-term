# Experiment: lookup table for glyph alpha boost

Date: 2026-05-21
Branch: `gpu-renderer-prototype`

## Hypothesis

GPU glyph upload applies `gpualpha()` to every grayscale glyph pixel to match the
punchier Xft text appearance.  The function performs a branch and integer math
for each pixel during glyph upload.  A 256-entry lookup table would preserve the
exact alpha mapping while reducing first-use glyph upload overhead in scroll and
repaint workloads.

## Patch tested

In `render/gpu.c`:

- changed `gpualpha()` to lazily initialize a 256-entry `unsigned char` table,
- returned `lut[a]` for each pixel,
- preserved the exact existing mapping:
  - `a < 16 -> 0`,
  - otherwise `MIN(255, (a - 16) * 280 / 239)`.

## Validation

With the patch applied:

```sh
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.

After rejection and revert:

```sh
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.

## A/B benchmark vs current GPU baseline

Benchmark output was saved to `/tmp/st-ab-alphalut-two.jsonl`.

Median kept-iteration results:

| Workload | Wall speedup | CPU ratio | Result |
|---|---:|---:|---|
| cursor_updates | `1.0011x` | `0.9903x` | tiny cursor win |
| repaint | `0.9933x` | `1.0105x` | repaint regression |
| scroll_ascii | `0.9940x` | `1.0360x` | scroll regression |

## Decision

Rejected and reverted.

The lookup table preserved behavior and gave a tiny cursor improvement, but it
regressed repaint and ASCII scroll.  Glyph upload is not the current limiting
factor for the benchmark mix, and the added lazy-initialization branch does not
pay for itself here.

Do not retry this alpha lookup table in the same form.
