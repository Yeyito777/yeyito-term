# Experiment: build with `-fno-plt`

Date: 2026-05-21
Branch: `gpu-renderer-prototype`

## Hypothesis

The renderer and parser paths call into several shared libraries (X11, GL,
FreeType, Fontconfig).  Compiling and linking with `-fno-plt` might reduce dynamic
call overhead without changing behavior or visuals.

## Patch tested

In `config.mk`:

```make
CFLAGS = -O3 -march=native -flto -fno-plt
LDFLAGS = -flto -fno-plt
```

## Validation

```sh
make -C ~/Config/st clean
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.

## A/B benchmark vs current GPU baseline

Benchmark output: `/tmp/st-ab-fnoplt-two.jsonl`.

Median kept-iteration results:

| Workload | Wall speedup | CPU ratio | Result |
|---|---:|---:|---|
| cursor_updates | `1.0163x` | `1.0008x` | small wall win, CPU neutral |
| repaint | `1.0128x` | `0.9702x` | small wall and CPU win |
| scroll_ascii | `1.0186x` | `1.2535x` | wall win, severe CPU regression |

## Decision

Rejected and reverted.

Although cursor and repaint looked mildly better, ASCII scroll CPU regressed by
about 25%.  A global compiler/linker flag should not be kept unless it is broadly
safe across workloads, especially under the user's requirement that CPU/GPU usage
stay tasteful.

Post-revert validation:

```sh
make -C ~/Config/st clean
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.  The working tree was clean and the installed binary still matched
the clean repo build.
