# Experiment: reduce GPU glyph atlas size to 1024x1024

Date: 2026-05-20
Branch: `gpu-renderer-prototype`

## Hypothesis

The GPU renderer currently allocates 2048x2048 alpha and color atlases.  Reducing
both to 1024x1024 could reduce memory footprint and first-use texture allocation
cost.  It might help startup/static resource use and still have enough room for
common ASCII/cursor/repaint workloads.

## Patch tested

In `render/gpu.c`, changed:

```c
gpu.atlasw = 2048;
gpu.atlash = 2048;
```

to:

```c
gpu.atlasw = 1024;
gpu.atlash = 1024;
```

## Validation

```sh
make -C ~/Config/st
make -C ~/Config/st test_gpu_regressions
```

Result: passed.

## A/B benchmark vs current GPU baseline

Median kept-iteration results:

| Workload | Wall speedup | CPU ratio | RSS change | Result |
|---|---:|---:|---:|---|
| cursor_updates | `0.953x` | `0.958x` | lower | wall regression |
| repaint | `1.003x` | `0.963x` | lower | tiny positive |
| scroll_ascii | `1.004x` | `1.204x` | lower | CPU regression |

## Decision

Rejected and reverted.

The smaller atlas reduced RSS a little and helped repaint slightly, but cursor wall
time regressed and ASCII scroll CPU regressed.  Atlas size also affects glyph cache
capacity and could regress real Unicode/emoji sessions, so this is not safe to keep.
